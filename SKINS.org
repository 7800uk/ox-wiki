#+TITLE: Writing a skin for ox-wiki

A skin is one library, called =ox-wiki-skin-NAME.el=, anywhere on =load-path=.
When a page asks for a skin ox-wiki has not seen, it requires that library by
name and expects it to have registered itself, so a skin someone else wrote
installs like any other package — nothing has to live inside this repository.

* What a skin owes ox-wiki

One call:

#+begin_src emacs-lisp
(org-wiki-define-skin 'name
  :title "Human-readable name"
  :stylesheets '("css/name.css")
  :body-class "skin-name"
  :page #'org-wiki-name-page)
#+end_src

=:stylesheets= are named relative to =org-wiki-directory=, the directory
=ox-wiki.el= itself sits in.  A skin shipped elsewhere can give absolute names
instead.

=:page= is the whole of it: a function of one argument, the page plist, returning
everything from =<body>= to =</body>=.  ox-wiki writes the doctype, the =<head>= and
the stylesheet elements around it.

More keys are optional:

| Key         | What it does                                                    |
|-------------+-----------------------------------------------------------------|
| =:html-class= | classes for =<html>=, after =client-nojs=; Citizen themes from there |
| =:own-toc=    | non-nil: leave MediaWiki's =#toc= out of the article, and draw the  |
|             | contents from the page plist's =:toc= instead                     |
| =:credit=     | a sentence for the footer, saying whose design the skin is      |
| =:scripts=    | scripts, named like =:stylesheets=, put in =<head>= in order        |
| =:modules=    | ResourceLoader modules to start once the page is parsed         |

* The page plist

| Key               | What it holds                                            |
|-------------------+----------------------------------------------------------|
| =:title=            | the page title, as HTML                                   |
| =:tagline=          | the line under the title, as plain text                   |
| =:subtitle=         | a line under that, as HTML, or nil                        |
| =:content=          | the body, already wrapped in =div.mw-parser-output=         |
| =:toc=              | the headings, for an =:own-toc= skin; see below            |
| =:modified=         | when the Org file last changed, as a Lisp time            |
| =:namespace-tabs=   | a menu plist: the left-hand tab group                     |
| =:action-tabs=      | a menu plist: Read, View source, View PDF, View history   |
| =:personal=         | a menu plist: the personal-tools row, or nil to draw none  |
| =:sidebar=          | a list of menu plists                                     |
| =:logo=             | =(:href URL :src DATA-URI)=                                 |
| =:search=           | =(:action URL :name FIELD :fields ALIST :sitename NAME)=, or nil to draw no search box |
| =:sitename=         | the wiki's name, as plain text, whether or not there is a search box |
| =:footer-info=      | a list of HTML strings                                    |
| =:footer-places=    | a list of link plists                                     |
| =:footer-buttons=   | a list of =(:src :href :alt)=                               |
| =:lang= =:slug= =:action= | for the =<html lang>= and the =<body>= classes              |

A *menu plist* is =(:id ID :label LABEL :links LINKS)=, and a *link plist* is
=(:text TEXT :href HREF :id ID :title TITLE :accesskey KEY :selected BOOL)=.

=:toc= is a flat list, in document order, of
=(:level N :section N :number "2.1" :id ANCHOR :text HTML)=, or nil when the page
has no contents.  It is filled in for every skin, but only an =:own-toc= skin
has the article without a =#toc= in it.

* Helpers you can lean on

| Function                  | Does                                              |
|---------------------------+---------------------------------------------------|
| =(org-wiki--items MENU SPAN)= | the =<li>= elements of a menu; SPAN wraps labels    |
| =(org-wiki--item LINK SPAN)=  | one of them                                       |
| =(org-wiki-body-class PAGE)=  | the =<body>= class list, =:body-class= included     |
| =(org-wiki--esc STRING)=      | HTML escaping                                     |
| =(org-wiki--attr NAME VALUE)= | ` NAME="VALUE"', or nothing when VALUE is empty   |

* Getting the stylesheet

No shipped skin's CSS is written here.  Each is the skin's own, taken from a
live wiki rather than built from the LESS sources, which import variables and
mixins from MediaWiki core and will not compile alone:

#+begin_src sh
curl 'https://en.wikipedia.org/w/load.php?modules=mediawiki.skins.legacy|skins.NAME.styles&only=styles&skin=NAME' \
     -o vendor/NAME/NAME.raw.css
#+end_src

For a skin Wikipedia does not run, ask a wiki that does; Citizen's came from
starcitizen.tools.  Put the icons that stylesheet references in
=vendor/NAME/images/= — they are in the skin's own repository, and an icon
ResourceLoader generates (=load.php?…&image=NAME=) is looked for as =NAME.svg= —
add the file to =BUILDS= in =tools/build-css.py=, and run it.  The result goes in =css/=, which is the only stylesheet directory the
package installs; =vendor/= is build-time only.  The build inlines the icons as data: URIs and
blanks out the project logo, which ox-wiki fills in per page.

Read the matching markup off the same wiki, with =?useskin=NAME=, and write
=:page= to produce it.

* Getting the scripts

A skin's JavaScript is taken the same way, without =only=styles=, which gives
the modules as a run of =mw.loader.impl()= calls:

#+begin_src sh
curl 'https://wiki.example/load.php?modules=skins.NAME.scripts|vue&skin=NAME' \
     -o vendor/NAME/NAME.raw.js
#+end_src

Ask for every module the skin will load, since nothing is fetched later: the
ones it loads on demand, and =vue= if any of them is a Vue app.  Add the file to
=BUILDS= in =tools/build-js.py=, with an override for any =config.json= the wiki
generated from its own settings, and list the result after =js/mediawiki.js= in
=:scripts=.  =:modules= names what to start, as a wiki's =RLPAGEMODULES= would.

=js/mediawiki.js= implements the part of =mw= that Citizen's modules use.  A new
skin may call more; a missing function shows up as an error in the console,
and belongs in that file.

* What differs between the shipped skins

Worth reading before writing another, because it is the range a skin can cover:
Vector puts the tab row along the top and the portlets in a left =#mw-panel=,
while MonoBook wraps everything in =#globalWrapper= and puts tabs and portlets
together in a left =#column-one=.  MonoBook also folds the namespace tabs and the
action tabs into a single =#p-cactions= list, and hides =#ca-view= with CSS, since
in MonoBook the namespace tab *is* "read".  Vector wraps every menu label in a
=<span>=; MonoBook does not.

Citizen goes further.  The sidebar becomes a drawer behind a header button, the
tabs become icon buttons beside the title, and the table of contents moves out
of the article into a side column, which is what =:own-toc= is for.  Its menus
are =<details>= elements, so they open without JavaScript, and it is the only
skin with scripts, which expect Org's outline as MediaWiki's =<section>= markup;
the skin rewrites it on the way out.  It takes its theme
from classes on =<html>= (=:html-class=), and it hides whichever tab is selected,
as Citizen does on a real wiki.

* A skin outside this repository

Nothing above needs the file to live here.  Put =ox-wiki-skin-foo.el= on
=load-path=, have it call =org-wiki-define-skin= with absolute =:stylesheets=, and
=#+WIKI_SKIN: foo= will find it.
