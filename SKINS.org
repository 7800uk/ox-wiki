#+TITLE: Writing a skin for ox-wiki

A skin is one library, called =ox-wiki-skin-NAME.el=, anywhere on =load-path=.
When a page asks for a skin ox-wiki has not seen, it requires that library by
name and expects it to have registered itself, so a skin someone else wrote
installs like any other package — nothing has to live inside this repository.

* What a skin owes ox-wiki

One call:

#+begin_src emacs-lisp
(org-wiki-define-skin 'name
  :title "Human-readable name"
  :stylesheets '("css/name.css")
  :body-class "skin-name"
  :page #'org-wiki-name-page)
#+end_src

=:stylesheets= are named relative to =org-wiki-directory=, the directory
=ox-wiki.el= itself sits in.  A skin shipped elsewhere can give absolute names
instead.

=:page= is the whole of it: a function of one argument, the page plist, returning
everything from =<body>= to =</body>=.  ox-wiki writes the doctype, the =<head>= and
the stylesheet elements around it.

* The page plist

| Key               | What it holds                                            |
|-------------------+----------------------------------------------------------|
| =:title=            | the page title, as HTML                                   |
| =:tagline=          | the line under the title, as plain text                   |
| =:subtitle=         | a line under that, as HTML, or nil                        |
| =:content=          | the body, already wrapped in =div.mw-parser-output=         |
| =:namespace-tabs=   | a menu plist: the left-hand tab group                     |
| =:action-tabs=      | a menu plist: Read, View source, View PDF, View history   |
| =:personal=         | a menu plist: the personal-tools row                      |
| =:sidebar=          | a list of menu plists                                     |
| =:logo=             | =(:href URL :src DATA-URI)=                                 |
| =:search=           | =(:action URL :name FIELD :fields ALIST :sitename NAME)=    |
| =:footer-info=      | a list of HTML strings                                    |
| =:footer-places=    | a list of link plists                                     |
| =:footer-buttons=   | a list of =(:src :href :alt)=                               |
| =:lang= =:slug= =:action= | for the =<html lang>= and the =<body>= classes              |

A *menu plist* is =(:id ID :label LABEL :links LINKS)=, and a *link plist* is
=(:text TEXT :href HREF :id ID :title TITLE :accesskey KEY :selected BOOL)=.

* Helpers you can lean on

| Function                  | Does                                              |
|---------------------------+---------------------------------------------------|
| =(org-wiki--items MENU SPAN)= | the =<li>= elements of a menu; SPAN wraps labels    |
| =(org-wiki--item LINK SPAN)=  | one of them                                       |
| =(org-wiki-body-class PAGE)=  | the =<body>= class list, =:body-class= included     |
| =(org-wiki--esc STRING)=      | HTML escaping                                     |
| =(org-wiki--attr NAME VALUE)= | ` NAME="VALUE"', or nothing when VALUE is empty   |

* Getting the stylesheet

Neither shipped skin's CSS is written here.  Both are MediaWiki's own, taken
from a live wiki rather than built from the LESS sources, which import variables
and mixins from MediaWiki core and will not compile alone:

#+begin_src sh
curl 'https://en.wikipedia.org/w/load.php?modules=mediawiki.skins.legacy|skins.NAME.styles&only=styles&skin=NAME' \
     -o vendor/NAME/NAME.raw.css
#+end_src

Put the icons that stylesheet references in =vendor/NAME/images/= — they are in
the skin's own repository — add the file to =BUILDS= in =tools/build-css.py=, and
run it.  The result goes in =css/=, which is the only stylesheet directory the
package installs; =vendor/= is build-time only.  The build inlines the icons as data: URIs and
blanks out the project logo, which ox-wiki fills in per page.

Read the matching markup off the same wiki, with =?useskin=NAME=, and write
=:page= to produce it.

* What differs between the two shipped skins

Worth reading before writing a third, because it is the range a skin can cover:
Vector puts the tab row along the top and the portlets in a left =#mw-panel=,
while MonoBook wraps everything in =#globalWrapper= and puts tabs and portlets
together in a left =#column-one=.  MonoBook also folds the namespace tabs and the
action tabs into a single =#p-cactions= list, and hides =#ca-view= with CSS, since
in MonoBook the namespace tab *is* "read".  Vector wraps every menu label in a
=<span>=; MonoBook does not.

* A skin outside this repository

Nothing above needs the file to live here.  Put =ox-wiki-skin-foo.el= on
=load-path=, have it call =org-wiki-define-skin= with absolute =:stylesheets=, and
=#+WIKI_SKIN: foo= will find it.
